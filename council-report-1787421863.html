Council Report

Question: How should the skill surface buried facts and figures as tables/bullets findable in an overview, for debate reference, before normalizing all 23 articles?

COUNCIL VERDICT

1. Agreement. A "The Facts" block at the top of each debate/exegesis article (separate pages rejected). Per-category schemas with real Date / Actor / Place-and-jurisdiction columns. A mandatory Qualifier column carrying the prose's hedge verbatim (one controlled taxonomy: stated / reported / attributed / likely / disputed). Every row anchors to the accordion item carrying the detail. The block is derived from prose: extraction only, zero new facts. Mechanical drift checks. Pilot first, then batch. One consolidated timeline for the 9-part serial.

2. Clashes resolved. Per-article only vs aggregation: a generated site-wide facts.html (rows link article + anchor) wins, because the user's real query ("who commissioned destruction in 303?") spans articles; four review seats independently rated this the strongest proposal. Unified vs per-category schema: per-category wins; a unified table re-buries who/when/where in a free-text cell.

3. Blind spots caught. Anchors landing inside collapsed accordions reveal nothing: the narration pages' hash-open script ships on every page with a Facts block. Five proposed status vocabularies collapse into one controlled taxonomy. There is no build step: enforcement lives in the skill's pre-ship validator. The retrofit reverses the legacy-freeze invariant and needs explicit authorization, which the user gave. Fact tables must be reconciled with the per-accordion fact cards, not become a third copy.

4. Recommendation. Debate schema: Claim | Actor | Date | Place | Source | Qualifier | detail anchor. Exegesis: Reading | Basis | Qualifier | anchor. Narration: no block; the serial hub gets one consolidated timeline across all parts. Validator gains: block present, ≥3 rows, anchors resolve, qualifier populated, hedge parity (prose hedge without row qualifier fails), substring overlap between row and target. facts.html is regenerated by the skill at every ship. Pilot text-destruction.html, review, then batch the remaining 22 with Arabic blocks byte-verified unchanged.

5. First step. Pilot text-destruction.html end to end today: schema, anchors, hedges, script, validator.

Peer review highlights

  • Strongest: Expansionist (4 seats), Contrarian (1 seat). Cross-article retrieval is the actual complaint; the aggregator answers it while inheriting the rigor mechanisms.
  • Blind spots: deferring the cross-article layer (leaves the 23-page hunt); unified schema without Date/Actor/Place columns (re-buries the facts); "regenerate on publish" assuming build machinery.
  • Missed by all five: anchors inside collapsed accordions need expand-on-hash JS; one controlled status taxonomy; enforcement needs a pre-ship hook; legacy-freeze reversal needs authorization; reconciling tables with existing fact cards.
Chairman: full synthesis

Agreement. Top-of-article Facts block; per-category schemas with date/actor/place-jurisdiction columns; mandatory verbatim-hedge Qualifier column; anchor per row; extraction-only derivation; mechanical checks; pilot then batch; consolidated serial timeline.

Clashes. Aggregation adopted (user's query spans articles); generated by the skill at ship time, never hand-synced. Per-category schemas adopted over unified.

Blind spots adopted. Hash-open script on all Facts pages; controlled taxonomy stated/reported/attributed/likely/disputed; enforcement in the pre-ship validator; append-only retrofit with Arabic byte-verification (user authorized); card/table reconciliation (cards = item-level Source/Claim; table = debate-reference claims with anchors).
