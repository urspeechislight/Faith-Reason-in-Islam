# Council Transcript: fact extraction and the overview layer

Date: 2026-08-22 14:04
Question: How should the skill surface buried facts/figures (tables/bullets findable in an overview) for debate reference, before the site-wide normalization pass?

## Framed question

See council-transcript summary: user cannot find which books were destroyed, who commissioned destruction, when, under whose rule, without hunting through prose. Facts must become tables/bullets findable in an overview; they are debate references. Grounded in real buried facts from text-destruction.html (Diocletian, February 303 CE, first edict; 4 Ezra late first century CE; 2 Maccabees "quite likely" scope) and three sibling fact-dense pages. Decisions: where facts live, form (unified vs per-category schema), anchor links, enforcement, 23-page retrofit, drift and qualifier-flattening prevention.

## Advisors (A=Expansionist, B=Contrarian, C=Executor, D=First Principles, E=Outsider for review; originals in order)

- Contrarian: the reference layer must be more rigorous than the prose; epistemic status column is the whole design (documented/reported/disputed/speculated); anchors non-negotiable; pilot text-destruction.html first, then batch; serial wants one consolidated timeline across all parts.
- First Principles: the table is an index, not a copy; fixed schema Item|Detail|Status|Source; Status gives hedges a home; append-only retrofit, prose byte-identical; hedge-parity validator check (prose "likely" + row "asserted" = fail); one article end-to-end first.
- Expansionist: debate prep is cross-article; generate one site-wide facts.html aggregating every article's tables, rows linking article+anchor; per-category schemas; qualifier column carries the hedge verbatim; substring drift check (cell key strings must appear in linked prose); retrofit = extraction only, zero new facts.
- Outsider: the unit of extraction is a claim with a qualifier and a locus, not a "fact"; schema Claim|Actor|Date|Place/Control|Qualifier|Detail-link; anchors non-negotiable and solve drift; token-overlap validator check; build the validator before the extractor.
- Executor: the facts block is a derived artifact, never hand-edited; per-category schemas (debate: Fact/Event|Date|Actor|Place & jurisdiction|Source locus|Status); no valid anchor, no row; regenerate on publish; Status carries the qualifier verbatim; keep rows machine-parseable for a future cross-article ledger.

## Chairman synthesis

**Agreement.** Top-of-article "The Facts" block (not separate pages); per-category schemas with real columns for date/actor/place-jurisdiction; a mandatory Qualifier column carrying the hedge verbatim from one controlled taxonomy; every row anchors to the accordion item carrying the detail; the block is derived from prose (extraction only, zero new facts); mechanical drift checks (anchor resolution, substring/token overlap between row and target, hedge parity); pilot one article first, then batch; one consolidated timeline for the serial.

**Clashes resolved.** Per-article only (B/D/E) vs aggregation (A): A wins on the user's actual query ("who commissioned destruction in 303?" spans pages); four review seats independently rated A strongest. The aggregator is generated by the skill at ship time, never hand-synced. Unified vs per-category: per-category wins (three seats flagged D's unified schema re-burying who/when/where).

**Blind spots adopted.** (1) Anchor links must open the accordion: the hash-handling script that narration pages already ship goes onto every page carrying a Facts block. (2) One controlled qualifier taxonomy (stated / reported / attributed / likely / disputed), used verbatim from prose. (3) Enforcement runs as the skill's existing pre-ship validator script, not a build step. (4) The retrofit reverses the legacy-freeze invariant and was explicitly authorized by the user; scope stays append-only (data-category, Facts block, generic-heading renames, hash script) with Arabic blocks byte-verified unchanged. (5) The Facts table and the per-accordion fact cards are reconciled: cards carry item-level Source/Claim; the table indexes debate-reference claims with anchors; a fact appears in both only when it is a debate reference. (6) The aggregator groups by category then article to avoid a scroll wall; browser find covers search.

**Recommendation.** Implement: per-category Facts schemas (debate: Claim|Actor|Date|Place & control|Source|Qualifier|detail anchor; exegesis: Reading|Basis|Qualifier|anchor; narration: no block, serial hub gets the consolidated timeline), controlled qualifier taxonomy, anchor-open script on all pages, validator additions (block present on debate/exegesis, ≥3 rows, anchors resolve, qualifier cell populated, hedge parity, substring overlap), facts.html aggregator regenerated at ship, pilot on text-destruction.html, then the 22-page batch with Arabic byte-verification.

**First step.** Pilot text-destruction.html end to end (schema, anchors, hedges, script, validator), review it, then batch.
